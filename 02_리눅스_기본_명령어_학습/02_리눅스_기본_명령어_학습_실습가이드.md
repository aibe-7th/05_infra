# 리눅스 기본 명령어 학습 통합 실습 가이드

## 1. 실습 개요 및 목표

본 실습은 현대 백엔드 및 클라우드 인프라 운영의 핵심 기반인 리눅스(Linux) 환경을 컨테이너 내부에서 직접 제어하는 실습입니다. 서버 패키지 관리, FHS 파일 시스템 탐색, 12-Factor App 원칙에 따른 환경변수 및 설정 파일 작성, 쉘 스크립트 실행 권한(`chmod`) 오류 해결 등 실무에서 매일 접하는 핵심 리눅스 명령어를 체득합니다.

> 💡 **[핵심 원리]**
> - **커널과 쉘의 역할 분담**: 커널(Kernel)은 하드웨어 자원을 직접 제어하는 운영체제의 핵심 엔진이며, 쉘(Shell: Bash)은 사용자의 명령어를 해석하여 시스템 콜(System Call)로 커널에 전달하는 인터페이스 프로그램입니다.
> - **Everything is a File**: 리눅스에서는 일반 파일, 디렉터리뿐만 아니라 하드웨어 디바이스, 프로세스 정보, 네트워크 소켓까지 모두 파일 시스템 트리(`/`) 아래 파일 형태로 추상화되어 관리됩니다.
> - **표준 스트림과 파이프라인**: 모든 리눅스 프로세스는 표준 입력(stdin, 0), 표준 출력(stdout, 1), 표준 에러(stderr, 2)를 기본으로 가집니다. 리다이렉션(`>`, `>>`)과 파이프(`|`)를 사용하면 명령어 출력을 파일로 저장하거나 다른 프로그램의 입력으로 자유롭게 연결할 수 있습니다.

### 핵심 학습 목표
1. 최신 공식 LTS Ubuntu 컨테이너 내부에서 APT 패키지 인덱스를 갱신하고 네트워크 전송 도구인 `curl`을 설치한다.
2. 리눅스 파일 시스템의 절대/상대 경로 탐색(`pwd`, `ls -la`)과 작업 디렉터리 생성 및 이동(`mkdir`, `cd`)을 숙달한다.
3. 표준 출력(`echo`), 환경변수(`export`, `printenv`), 리다이렉션(`>`, `>>`)을 활용하여 애플리케이션 환경설정 파일(`app.env`)을 생성한다.
4. 배포 스크립트를 작성하고 파일 내용 조회/검색(`cat`, `head`, `tail`, `grep`, 파이프 `|`) 및 파일 실행 권한 오류(`Permission denied`)를 `chmod`로 해결한다.
5. 파일 복사(`cp`), 이동 및 이름 변경(`mv`), 삭제(`rm`)를 수행하고 컨테이너 자원을 완벽히 정리한다.

## 2. 실습 환경 및 준비

본 실습은 호스트 OS(Windows/macOS)의 환경 차이나 권한 제약을 배제하기 위해, Docker로 구동된 최신 LTS Ubuntu 컨테이너 내부 쉘에서 안전하게 진행됩니다.

- **작업 환경**: Docker 공식 최신 LTS Ubuntu 컨테이너 내부 대화형 Bash 쉘
- **컨테이너 진입 명령**:
  ```bash
  docker run -it --name linux-practice ubuntu:26.04 bash
  ```
  *(만약 이전 실습으로 `linux-practice` 컨테이너가 이미 중지 상태로 존재한다면 `docker start -ai linux-practice`로 재진입합니다.)*
- **실습 디렉터리**: 컨테이너 내부 `/practice`
- **주요 실습 도구**: `apt`, `curl`, `bash`, `chmod`, `grep`, `env`

> ⚠️ **[주의 사항]**
> - 컨테이너 내부 쉘 프롬프트가 `root@<container-id>:/#` 형태로 출력되고 있는지 확인하십시오. 모든 실습 명령어는 호스트 터미널이 아닌 **컨테이너 내부 쉘**에서 순차 실행됩니다.
> - `root` 사용자는 모든 시스템 파일에 쓰기 권한을 가지므로, 실습 경로(`/practice`) 외의 리눅스 시스템 디렉터리(`/bin`, `/etc`, `/lib` 등)를 임의로 수정하거나 삭제하지 않도록 주의합니다.

## 3. 실습 절차

### Step 1. 리눅스 패키지 관리자로 curl 설치하기

컨테이너 내부 리눅스 환경에서 APT 패키지 관리자를 사용하여 네트워킹 전송 도구인 `curl`을 설치하고 버전을 확인합니다.

```bash
# 1. 패키지 인덱스 메타데이터 갱신
apt update

# 2. curl 패키지 무인 설치 (-y)
apt install -y curl

# 3. 설치 상태 및 버전 검증
curl --version
```

- **옵션 및 구문 설명**:
  - `apt update`: 원격 패키지 저장소의 최신 소프트웨어 목록 인덱스를 로컬 캐시로 동기화합니다.
  - `apt install -y curl`: `curl` 패키지 및 관련 의존성(라이브러리, 인증서 등)을 설치하며 사용자 확인 프롬프트를 자동으로 승인(`-y`)합니다.
  - `curl --version`: 설치된 curl의 버전, 지원 프로토콜(HTTP, HTTPS 등) 및 암호화 엔진(OpenSSL)을 확인합니다.

> 📌 **[기대 출력 확인]**
> ```text
> curl 8.18.0 (aarch64-unknown-linux-gnu) libcurl/8.18.0 OpenSSL/3.5.5 ...
> Protocols: dict file ftp ftps gopher ... http https ...
> Features: alt-svc AsynchDNS HSTS HTTP2 HTTPS-proxy IPv6 ...
> ```
> `curl 8.x.x` 이상의 최신 버전과 `Protocols:`에 `http`, `https`가 정상 출력되어야 합니다.

### Step 2. 위치 확인과 작업 디렉터리 생성

현재 작업 위치를 확인하고 실습용 전용 디렉터리 `/practice`를 생성하여 이동합니다.

```bash
# 1. 현재 작업 경로 및 루트 디렉터리 파일 목록 확인
pwd
ls
ls -la

# 2. 실습용 디렉터리 생성 및 이동
mkdir /practice
cd /practice

# 3. 변경된 작업 경로 확인
pwd
```

- **옵션 및 구문 설명**:
  - `pwd`: 현재 작업 중인 절대 경로(Print Working Directory)를 화면에 출력합니다.
  - `ls -la`: 숨김 파일(`.`)을 포함하여 모든 파일의 파일 유형, 권한, 소유자/소유그룹, 용량, 수정 시간을 상세 출력합니다.
  - `mkdir /practice`: 루트(`/`) 경로 하위에 신규 디렉터리 `practice`를 생성합니다.
  - `cd /practice`: 현재 쉘의 작업 위치를 `/practice` 디렉터리로 변경합니다.

> 📌 **[기대 출력 확인]**
> ```text
> root@dca85abecf4b:/# pwd
> /
> root@dca85abecf4b:/# cd /practice
> root@dca85abecf4b:/practice# pwd
> /practice
> ```
> 프롬프트 경로가 `/practice`로 바뀌고, `pwd` 실행 결과로 `/practice`가 표시되어야 합니다.

---

### Step 3. echo와 리다이렉션으로 환경변수 및 설정 파일 작성

문자열 출력, 환경변수 등록/조회, 리다이렉션 연산자를 활용하여 12-Factor App 원칙에 부합하는 환경설정 파일(`app.env`)을 직접 생성합니다.

```bash
# 1. 표준 출력 및 내장 환경변수 출력
echo "Hello Linux"
echo $HOME

# 2. 현재 쉘 세션 환경변수 등록 및 조회
export APP_ENV=development
export PORT=8080
printenv APP_ENV
printenv PORT

# 3. 리다이렉션 연산자를 이용한 설정 파일 생성
echo "APP_ENV=development" > app.env
echo "PORT=8080" >> app.env

# 4. 파일 내용 확인
cat app.env
```

- **옵션 및 구문 설명**:
  - `echo "문자열"`: 인자로 전달된 문자열을 표준 출력(stdout)으로 출력합니다.
  - `export 변수명=값`: 현재 쉘 세션 및 이후 생성되는 자식 프로세스에서 참조할 수 있는 환경변수를 등록합니다.
  - `printenv [변수명]`: 지정한 환경변수의 현재 값을 출력합니다.
  - `>` (Overwrite): 명령어 출력을 파일로 전송하되, 파일이 없으면 생성하고 이미 존재하면 기존 내용을 완전히 덮어씁니다.
  - `>>` (Append): 명령어 출력을 파일로 전송하되, 파일 맨 끝에 새로운 행을 이어붙입니다.

> 📌 **[기대 출력 확인]**
> ```text
> APP_ENV=development
> PORT=8080
> ```
> `cat app.env` 실행 시 두 개의 설정 키-값 쌍이 누락이나 중복 없이 정확히 출력되어야 합니다.

### Step 4. 배포 스크립트 작성

실무 배포 자동화에 사용되는 쉘 스크립트(`deploy.sh`)를 Heredoc 구문을 활용하여 생성합니다.

```bash
cat <<'SCRIPT_EOF' > deploy.sh
#!/bin/bash
echo "Starting deployment service..."
echo "Target server environment: ${APP_ENV:-local}"
echo "Listening port: ${PORT:-8080}"
echo "Deployment completed successfully."
SCRIPT_EOF

# 생성된 파일 권한 및 상세 정보 확인
ls -l deploy.sh
```

- **옵션 및 구문 설명**:
  - `cat <<'SCRIPT_EOF' > deploy.sh`: `SCRIPT_EOF` 표식이 나올 때까지 입력된 여러 줄의 텍스트를 `deploy.sh` 파일로 일괄 저장합니다. (따옴표 `'SCRIPT_EOF'`는 내부 변수 `${APP_ENV}`가 파일 작성 시점에 미리 치환되지 않고 그대로 저장되도록 보존합니다.)
  - `#!/bin/bash` (Shebang): 스크립트를 실행할 때 사용할 쉘 인터프리터 경로를 커널에 지정합니다.
  - `${APP_ENV:-local}`: `APP_ENV` 환경변수가 설정되어 있으면 그 값을 사용하고, 없으면 기본값인 `local`을 사용하라는 Bash 매개변수 확장 구문입니다.

> 📌 **[기대 출력 확인]**
> ```text
> -rw-r--r-- 1 root root 181 Sep  4 11:04 deploy.sh
> ```
> 기본 파일 권한이 `-rw-r--r--`(읽기/쓰기만 가능, 실행 비트 `x` 없음)로 생성된 것을 확인합니다.

### Step 5. 파일 내용 확인과 문자열 검색

생성된 스크립트와 설정 파일을 다양한 리눅스 텍스트 유틸리티와 파이프(`|`)를 통해 조회하고 필요한 키워드를 검색합니다.

```bash
# 1. 파일 전체 내용 조회
cat deploy.sh

# 2. 상단 및 하단 분할 라인 확인
head -n 3 deploy.sh
tail -n 3 deploy.sh

# 3. 설정 파일에서 키워드 필터링
grep "APP_" app.env

# 4. 라인 번호(-n)를 포함한 키워드 검색
grep -n "echo" deploy.sh

# 5. 파이프(|)와 대소문자 무시(-i) 옵션을 조합한 검색
cat deploy.sh | grep -i "server"
```

- **옵션 및 구문 설명**:
  - `cat [파일]`: 파일 전체 내용을 표준 출력으로 출력합니다.
  - `head -n 3` / `tail -n 3`: 파일의 처음 3줄 또는 마지막 3줄만 분할 출력합니다. (로그 파일 분석 시 매우 유용)
  - `grep [검색어] [파일]`: 파일 내부에서 특정 문자열 패턴이 포함된 라인을 검색합니다.
  - `-n`: 검색된 라인의 행 번호(Line Number)를 함께 표시합니다.
  - `-i`: 영문 대소문자를 구분하지 않고 검색합니다.
  - `|` (파이프): 앞선 명령어의 표준 출력을 뒤 명령어의 표준 입력으로 직접 연결합니다.

> 📌 **[기대 출력 확인]**
> ```text
> # grep -n "echo" deploy.sh 출력
> 2:echo "Starting deployment service..."
> 3:echo "Target server environment: ${APP_ENV:-local}"
> 4:echo "Listening port: ${PORT:-8080}"
> 5:echo "Deployment completed successfully."
> 
> # cat deploy.sh | grep -i "server" 출력
> echo "Target server environment: ${APP_ENV:-local}"
> ```

### Step 6. 파일 권한 오류 확인과 chmod로 해결

실행 권한(`x`) 부재로 인한 `Permission denied` 오류를 직접 재현하고, `chmod` 명령어로 실행 권한을 부여하여 스크립트를 정상 실행합니다.

```bash
# 1. 실행 권한 없는 상태에서 실행 시도 (오류 재현)
./deploy.sh

# 2. 기호 모드로 실행 권한(+x) 부여 및 권한 확인
chmod +x deploy.sh
ls -l deploy.sh

# 3. 스크립트 정상 실행
./deploy.sh

# 4. 실무 표준 8진수 숫자 모드 권한 적용 실습
chmod 755 deploy.sh
chmod 644 app.env
ls -l
```

- **옵션 및 구문 설명**:
  - `./deploy.sh`: 현재 디렉터리(`.`)의 `deploy.sh` 실행 파일을 직접 실행합니다.
  - `chmod +x deploy.sh`: 소유자, 그룹, 기타 사용자 모두에게 실행(`x`) 권한을 추가합니다.
  - `chmod 755 deploy.sh`: 소유자 `rwx`(7), 그룹 `r-x`(5), 기타 사용자 `r-x`(5) 권한을 부여하는 실무 실행 파일 표준 권한입니다.
  - `chmod 644 app.env`: 소유자 `rw-`(6), 그룹 `r--`(4), 기타 사용자 `r--`(4) 권한을 부여하는 실무 설정/데이터 파일 표준 권한입니다.

> ⚠️ **[주의 사항]**
> - 실행 권한(`x`)이 없는 상태에서 `./deploy.sh`를 실행하면 `bash: ./deploy.sh: Permission denied` 오류가 발생하며 프로세스 종료 코드(Exit Code)는 `126`이 반환됩니다.
> - 환경변수 출력은 앞선 Step 3 세션이 유지된 경우 `Target server environment: development`, 새 세션인 경우 기본값인 `Target server environment: local`이 출력됩니다.

> 📌 **[기대 출력 확인]**
> ```text
> # 1. 실행 권한 부여 전
> bash: ./deploy.sh: Permission denied
> 
> # 2. chmod +x 적용 후 정상 실행
> Starting deployment service...
> Target server environment: development (또는 local)
> Listening port: 8080
> Deployment completed successfully.
> 
> # 3. ls -l 확인
> -rw-r--r-- 1 root root  30 Sep  4 11:04 app.env
> -rwxr-xr-x 1 root root 181 Sep  4 11:04 deploy.sh
> ```

### Step 7. 파일 복사·이동·삭제 실습

생성한 파일들을 복사(사본 생성), 이동(파일명 변경), 삭제하여 리눅스 파일 관리 기본기를 마무리합니다.

```bash
# 1. 파일 백업 사본 생성
cp deploy.sh deploy-backup.sh
ls -l

# 2. 파일 이름 변경 (이동)
mv deploy-backup.sh archived.sh
ls -l

# 3. 불필요한 백업 파일 삭제
rm archived.sh
ls -l
```

- **옵션 및 구문 설명**:
  - `cp [원본] [대상]`: 지정한 이름으로 새 파일 사본을 복제합니다.
  - `mv [원본] [대상]`: 파일의 디렉터리 위치를 이동하거나 파일명을 변경합니다.
  - `rm [대상]`: 지정한 파일을 영구 삭제합니다. (리눅스 CLI에는 윈도우/맥의 휴지통 기능이 없으므로 삭제 시 복구 불가능)

> 📌 **[기대 출력 확인]**
> ```text
> -rw-r--r-- 1 root root  30 Sep  4 11:04 app.env
> -rwxr-xr-x 1 root root 181 Sep  4 11:04 deploy.sh
> ```
> `archived.sh` 파일이 완전히 제거되고 원본 `app.env`와 `deploy.sh` 2개 파일만 남아야 합니다.

## 4. 실무 트러블슈팅 가이드

실제 리눅스 컨테이너 검증(`04_proven/02_리눅스_기본_명령어_학습.md`) 과정에서 확인된 핵심 오류와 조치 방법입니다.

### 1) `debconf: unable to initialize frontend: Dialog` 안내 메시지
- **원인**: 컨테이너 환경은 GUI/TTY 프론트엔드 대화창 도구(`Dialog`)가 설치되어 있지 않아, `apt install` 시 비대화형(Noninteractive) 모드로 자동 전환된다는 안내 문구입니다.
- **해결책**: 이는 오류가 아니며 정상적인 폴백 동작입니다. 의존성 패키지와 소프트웨어가 완벽히 설치되므로 안심하고 다음 단계를 진행합니다.

### 2) 스크립트 실행 시 `Permission denied`와 종료 코드 126
- **원인**: 리눅스 커널은 파일의 권한 비트(Mode)에 실행 권한(`x`)이 명시적으로 부여되어 있지 않으면 보안을 위해 해당 파일의 실행을 강제 차단합니다.
- **해결책**: 
  - `ls -l deploy.sh`를 실행하여 4번째 자리(`-rw-r--r--`)에 `x`가 있는지 확인합니다.
  - `chmod +x deploy.sh` 또는 `chmod 755 deploy.sh`를 실행하여 실행 권한을 부여한 뒤 다시 `./deploy.sh`를 구동합니다.
  - 참고: 명령어 자체를 찾을 수 없을 때의 종료 코드는 `127`이며, 권한 부족으로 차단된 경우의 종료 코드는 `126`입니다.

### 3) 환경변수 출력 불일치 (`development` vs `local`)
- **원인**: `deploy.sh` 내부의 `${APP_ENV:-local}`은 현재 세션에 `export APP_ENV=development`가 유지되어 있으면 `development`를 출력하고, 컨테이너 재접속이나 새 세션으로 진입하여 환경변수가 초기화된 경우 기본값인 `local`을 출력합니다.
- **해결책**: 두 경우 모두 스크립트의 기본값 fallback 문법이 정상 동작한 결과입니다. 만약 `development` 출력을 확인하고 싶다면 `export APP_ENV=development`를 다시 입력하고 실행합니다.

### 4) 리다이렉션 연산자 `>`와 `>>` 혼동으로 인한 데이터 유실
- **원인**: 기존 파일에 내용을 추가해야 하는 상황에서 `>>`(이어쓰기) 대신 `>`(덮어쓰기)를 사용하면 파일 내의 기존 내용이 한순간에 영구 삭제됩니다.
- **해결책**: 설정 파일에 추가 항목을 기입할 때는 반드시 `>>` 연산자를 사용해야 하며, 중요한 설정 파일은 작업 전 `cp app.env app.env.bak`처럼 사본을 먼저 확보하는 습관을 들입니다.

## 5. 실습 자원 정리 (Cleanup)

실습을 마친 후 컨테이너 쉘 세션을 종료하고 호스트 머신에서 실습 컨테이너를 영구 삭제합니다.

```bash
# 1. 컨테이너 쉘 세션 종료 (호스트 터미널로 복귀)
exit

# 2. 호스트 터미널에서 정지된 실습 컨테이너 영구 삭제
docker rm linux-practice

# 3. 잔여 컨테이너 정리 상태 확인 (출력 결과가 비어 있어야 함)
docker ps -a
```

- **정리 결과 검증**:
  - 컨테이너가 정상 종료되면 호스트 터미널로 돌아옵니다.
  - `docker rm linux-practice` 실행 후 `docker ps -a` 목록에 `linux-practice`가 사라졌는지 확인합니다.
